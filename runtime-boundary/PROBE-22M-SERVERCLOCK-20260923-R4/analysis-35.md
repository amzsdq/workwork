# R4 PRODUCTIVE_CAP versus OPERATING_CAP audit

## Definitions

OPERATING_CAP should be the maximum policy-approved invocation envelope after safety margin and repeated reliability validation.

PRODUCTIVE_CAP should describe how late substantial useful work can continue while still leaving a reliable completion envelope. It may be lower than OPERATING_CAP/HARD_CAP because close/checkpoint work consumes the tail.

## Evidence needed for PRODUCTIVE_CAP

- last normal task admission anchors across clean near-cap runs,
- task-size distribution/profile,
- close-overhead distribution,
- whether late admissions caused overshoot or failed close,
- productive span/substantive units without fabricated active seconds.

## Why R4 alone cannot set it

R4 is a single W3 boundary probe and close-overhead instrumentation is limited. Even a clean 22m pass establishes survival/close feasibility, not a universal productive cutoff.

## Phase C use

P2/P3 policy experiments should compare how much useful work is retained near the tail while preserving clean close. PRODUCTIVE_CAP should emerge from those decisions rather than be defined as HARD_CAP minus an arbitrary minute.
